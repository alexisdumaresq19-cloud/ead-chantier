# The iPhone app: how it is put together

"EAD" on the App Store is a native shell around the live site. Capacitor 8 gives a `WKWebView` that loads https://ead-chantier.vercel.app, plus a bridge that lets the site's pages call a few native plugins. Nothing of the site is bundled: a deployment of the site reaches the app at once, and a new upload is only needed when the shell itself changes. The steps to build, try and upload it on a Mac are in [MAC.md](MAC.md), written for the person (or the agent) at that Mac, in French.

## Decisions and their reasons

| Decision                                                                 | Why                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capacitor 8.6.2 with Swift Package Manager                               | No CocoaPods (no Ruby, no `pod install`): Xcode resolves everything. The Capacitor framework itself comes as a binary from `capacitor-swift-pm`; each plugin is a local package in `node_modules/@capacitor/…`.                                                                                             |
| Loads the live site (`server.url`), bundles nothing                      | One app, one deployment. The site's service worker and IndexedDB keep it usable offline, as in the installed web app.                                                                                                                                                                                       |
| iPhone only, iOS 15 minimum                                              | The team's phones. `TARGETED_DEVICE_FAMILY = 1`, no iPad orientations, not offered on Mac or Vision Pro. iOS 15 is what Capacitor 8 supports at the lowest.                                                                                                                                                 |
| Name "EAD", identifier `ca.allendumaresq.ead`                            | The identifier is fixed for good by the first upload; until then `scripts/ios-set-id.sh` changes it in every file that names it.                                                                                                                                                                         |
| Unlisted App Store app, TestFlight first                                 | A private app for EAD's team without managing devices. Requesting unlisted distribution and submitting for review are the owner's decisions, made by hand.                                                                                                                                                 |
| Automatic signing with an App Store Connect API key kept outside the repository | No certificate or profile to manage by hand: `xcodebuild -allowProvisioningUpdates -authenticationKey…` creates them. The key (`.p8`), its ids and the Team ID live in `~/.appstoreconnect/` on the Mac: `ASC_KEY_PATH`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_TEAM_ID` are exported from `~/.appstoreconnect/ead.env`, which `~/.zshrc` sources and the scripts read themselves (a command run by an agent does not see what was added to `~/.zshrc` after its session started). The team needs one registered iPhone: automatic signing archives with a development profile first, and Apple makes none for a team without devices (MAC.md 4.6). |

## The web view

- **Background, status bar, safe areas.** The web view is the app's black (`#0b0d10`) while a page loads. It runs under the status bar and the home indicator (`contentInset: "never"`); the site already keeps clear of them with `viewport-fit=cover` and `env(safe-area-inset-*)`. The status bar text is light (`UIStatusBarStyleLightContent`), over the site's black header.
- **User agent.** `EADApp/<version>` is appended to WebKit's own. `<version>` is `const version` in `capacitor.config.ts`, which must equal `MARKETING_VERSION` (checked by `scripts/ios-sync.sh` and by the association file's test).
- **Splash screen.** The launch storyboard shows the logo; the plugin keeps it over the web view until the page calls `SplashScreen.hide()`, or for at most 3 seconds (`launchAutoHide`). The plugin blocks touches while it shows, hence the short limit. `offline.html` hides it too.
- **Swipe back.** `allowsBackForwardNavigationGestures`, set in `EADViewController.capacitorDidLoad`. It walks the web view's history, which includes the single-page app's `pushState` entries.
- **Links to other sites** are opened in Safari by Capacitor (`WebViewDelegationHandler.decidePolicyFor`): anything that does not start with `server.url`, and every `target="_blank"` (`createWebViewWith`). `mailto:` and `tel:` go to Mail and Phone the same way.
- **No JavaScript dialogs.** Capacitor answers `alert()` and `confirm()` with English "Ok"/"Cancel" buttons; the site uses its own dialogs.

## The offline page

`server.errorPath: "offline.html"` makes Capacitor load `capacitor://localhost/offline.html` from its `didFail` and `didFailProvisionalNavigation` delegate methods, for any navigation that fails, the first one included. With the site's service worker in control, an offline launch is answered by the worker and never fails, so the page shows only when neither the network nor the worker can answer (first launch without a network, server down).

Capacitor would also show it for a navigation that was only interrupted: `NSURLErrorCancelled` (one page replaced by another before it arrived) and WebKit's error 102 (a download, or a type the web view does not display). `NavigationFilter` in `EADViewController.swift` sits between the web view and Capacitor's delegate and drops those two. Capacitor also loads the offline page without saying which address failed. For a failed page of the site, the filter loads the offline page itself with that page's path and query after `#` (`offline.html#/i/abc`, read from the error's `NSURLErrorFailingURLErrorKey`), so that an invitation or a universal link opened without a network is not lost. Everything else is forwarded unchanged through Objective-C message forwarding; Capacitor's own first-load step (making the web view opaque again) still happens, in its `didFinish` for the offline page.

The page checks the server with a `no-cors` request to `/api/version` (any answer means the network is back). On load it does so once quietly and returns to the site if it answers, at most once every 30 seconds, so a load that only stumbled costs a blink. "Réessayer" checks again and returns with `location.replace` to the address after `#` (only a path of the site: it must start with a single `/`; anything else returns to the home screen), so a swipe back never lands on the offline page. It promises nothing else.

## App-Bound Domains (the switch)

`appBoundDomains` in `capacitor.config.ts` sets `limitsNavigationsToAppBoundDomains`; `Info.plist` lists the domains under `WKAppBoundDomains` (at most 10, each reduced to its registrable domain; `vercel.app` is a public suffix, so `ead-chantier.vercel.app` stays as it is): `ead-chantier.vercel.app` and `localhost`. The reasoning comes from WebKit's source (github.com/WebKit/WebKit, read on 2026-11-20) and Capacitor's:

- **Why it is on.** `WebPage::updatePreferences` (Source/WebKit/WebProcess/WebPage/WebPage.cpp) turns service workers off in any app that is not a browser unless the page was created with `limitsNavigationsToAppBoundDomains`. With the switch off there is no service worker at all, whatever `Info.plist` says, and the app would lose what opens kept plans without a network.
- **Which navigations stay allowed.** `WebPageProxy::decidePolicyForNavigationAction` asks the app's policy delegate first and checks app-bound domains only for a navigation the delegate allowed (`setIsNavigatingToAppBoundDomainAndCheckIfPermitted`). A main-frame navigation to an unlisted domain then fails with a provisional-navigation error. In this app it never gets there: Capacitor's `decidePolicyFor` hands every address that does not start with `server.url` to Safari and cancels it, so links to other sites open in Safari as before. Sub-resources (images from storage, `fetch` to other hosts) are not navigations and still load.
- **The bundled pages.** WebKit counts any main-frame address whose host is `localhost` as app-bound (`shouldTreatURLProtocolAsAppBound`), so `capacitor://localhost/offline.html` loads and keeps the bridge even without the `localhost` entry; the entry stays, as Capacitor's documentation for `server.hostname` asks.
- **The bridge's script injection.** Capacitor injects `native-bridge.js` as a `WKUserScript` and listens with a script message handler. In an app with `WKAppBoundDomains`, WebKit ignores user scripts and `evaluateJavaScript` in frames outside the app-bound domains (`LocalFrame::injectUserScriptImmediately`, `WebPage::runJavaScriptInFrameInScriptWorld`: "Ignoring user script injection for non-app bound domain"). Both of ours are listed, so the bridge works on the site and on the offline page.
- **Cookies** and storage of the listed domains work as before.

What only a run proves: that the service worker controls the page and the plugins answer, both shown by `/diagnostic`. MAC.md 4.5 has the decision table. Since the switch off never gives a service worker, it goes off only if the bridge is missing with it on; the app then works online only, and that is written in the journal.

## Universal links

The entitlement claims `applinks:ead-chantier.vercel.app`. Apple fetches `/.well-known/apple-app-site-association` through its CDN; the route answers `200 application/json`, no redirect, when `IOS_APP_ID` (`TEAMID.bundle.identifier`) is set on the server, and 404 otherwise (`force-dynamic`, so changing the variable needs no build; the fallback rewrite of `next.config.ts` only applies to addresses no route matches, and the service worker leaves `/.well-known/*` to the network). Every screen opens the app except, in order: `/api/*`, `/files/*`, `/_next/*`, `/.well-known/*`, the public pages `/confidentialite*` and `/soutien*` (read by anyone, and the App Store's privacy and support links must stay in the browser), and the site's own files (`/brand/*`, `/sw.js`, the manifest, the icons). Invitations (`/i/…`, `/j/…`) and `/diagnostic` open the app. What the app does with an incoming link is the site's part (`src/client/native`, the App plugin's `appUrlOpen`).

## Privacy manifest and purpose strings

- Capacitor ships its own `PrivacyInfo.xcprivacy` in `Capacitor` and `CapacitorCordova`: no tracking, no collected data, no required-reason API. The plugins (`app`, `share`, `filesystem`, `file-viewer`, `splash-screen`) ship none in their packages; `filesystem` returns file creation and modification dates (`stat`), read through `IONFilesystemLib` (github.com/ionic-team/ion-ios-filesystem, tag 2.0.1, the exact version the plugin asks for). That library and `IONFileViewerLib` (ion-ios-fileviewer) ship no privacy manifest; their sources were searched for the other required-reason APIs (disk space, boot time, user defaults, active keyboards) and use none. The plugins are compiled into the app, so the app's own manifest declares that one category: `NSPrivacyAccessedAPICategoryFileTimestamp` with reason `C617.1` (files inside the app's container), and no tracking. It declares no collected data types: what the team's accounts hold is described in App Store Connect's App Privacy section and on `/confidentialite`. If Apple names another API (`ITMS-91053`), add it with the reason that matches the actual use.
- Purpose strings, one plain French sentence each, for exactly what the site uses: the camera (`<input capture>` for site photos), the microphone (`getUserMedia` for the report's dictation) and adding to the photo library (saving a photo from the share sheet). Choosing a photo uses the system picker, which needs no permission. Capacitor grants the page's media capture requests itself, so the person sees only the system's prompt.
- `ITSAppUsesNonExemptEncryption = false`: the app uses only the system's HTTPS.

## Debug builds

- `EAD_START_PATH=/diagnostic` in the launch environment opens the site at that address (`scripts/ios-sim.sh` passes it through `SIMCTL_CHILD_EAD_START_PATH`). Compiled in `#if DEBUG` only. It replaces the server URL and allows the site's host by name, since Capacitor treats an address that does not start with `server.url` as another site.
- The web view is inspectable from Safari's Develop menu in debug builds (Capacitor's default).
